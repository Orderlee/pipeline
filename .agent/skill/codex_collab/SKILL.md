# Codex collaboration

로직을 바꾸는 비자명한 수정, API 변경, 코드 리뷰에 쓴다. 파일 이동·분할처럼 동작 보존이 핵심이면 `codex_refactor`를 쓴다. 오탈자·한 줄 import·명백한 null 방어는 직접 처리한다.

1. 대상, 현재 동작, 원하는 동작, 호환성·성능·테스트 제약을 코드와 호출부에서 확인한다.
2. Codex에는 해당 맥락과 제약만 주고, 변경 위치·위험·경계 사례·필요 테스트를 **read-only 제안**으로 요청한다. 비밀값은 제외한다.
3. 제안을 사용자에게 그대로 제시하고 적용/수정/재검토/취소 승인을 받는다. 어려운 독립 해법 비교는 `codex_arbitration`으로 넘긴다.
4. 승인 범위만 적용한다. 서명 변경은 호출부를 검색하고, 운영 영향 변경은 staging에서 먼저 검증한다.
5. 변경 범위에 맞춰 `ruff check`, 관련 unit test, 필요 시 정의 로드를 확인한다.

## 제약

- 하위 에이전트는 파일을 수정·커밋하지 않는다.
- 사용자 목표와 제안이 충돌하면 둘 다 드러내고 결정은 사용자에게 둔다.
- DB 마이그레이션은 `codex_db_migration` 절차와 저장소의 forward-only 규칙을 따른다.
