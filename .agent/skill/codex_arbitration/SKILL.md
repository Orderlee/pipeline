# Codex arbitration

어려운 문제를 두 에이전트가 **서로의 답을 보지 않고** 풀고, 검증 가능한 기준으로 사용자가 선택할 때만 쓴다. 단순 변경은 `codex_collab`, 구조 이동은 `codex_refactor`를 쓴다.

1. 입력·출력·제약·경계 사례·성공 테스트를 한 장의 명세로 확정한다. 테스트 기준이 없으면 먼저 만든다.
2. 두 에이전트에 같은 명세만 전달한다. 한쪽 답·힌트·파일 변경 권한은 전달하지 않는다.
3. 같은 테스트로 비교한다: 정확성, 시간/공간, 유지보수성, 처리한 경계 사례, 가정·위험.
4. 두 답과 비교표를 사용자에게 보여 `채택 / 결합안 / 재명세 / 추가 중재`를 받는다.
5. 선택안을 적용한 뒤 회귀 테스트와 관련 lint를 실행한다.

## 제약

- 독립성 훼손, 비밀값 포함 가능성, 검증 수단 부재면 호출하지 않는다.
- 하위 에이전트는 제안만 하고 파일을 수정하지 않는다.
- 마이그레이션은 forward-only이며 `DROP`/`TRUNCATE`를 제안하지 않는다.
